# Bigtable production recovery service plan

This plan exercises the production factories delivered under Accepted ADR-0165.
It is a correctness lease, not the seven-cell admission diagnostic or the unrestricted formal performance assessment.
The owner authorized verification on the implementation branch and charging on 2026-09-11; the existing USD 20 aggregate ceiling still applies.
No service result is recorded here.

## Fixed resources and workload

Use project `flink-gcp`, instance `flink-s2-1789087763-4d81c5`, zone `us-central1-b`, one SSD node and cluster `stage2-c1`.
The fresh `production-recovery` manifest contains the random owner label and these exact tables, in worker order:

1. `recovery-datastream-flink1`: Flink 1.20.4, DataStream builder.
2. `recovery-table-flink1`: Flink 1.20.4, Table aggregate factory/runtime provider.
3. `recovery-datastream-flink2`: Flink 2.2.1, DataStream builder.
4. `recovery-table-flink2`: Flink 2.2.1, Table aggregate factory/runtime provider.

Each recovery table has `cf`, INT64 SUM `agg`, and raw no-GC `flink_commit`.
The unused `cf` follows the existing lease provisioning shape.
The three additional tables `marker-missing`, `marker-gc` and `marker-typed` retain the existing negative metadata fixtures.
Profiles are transactional `single-cluster`, transaction-disabled `no-tx`, and `multi-cluster`.
No shared fixture, cloud execution host, checkpoint bucket, IAM mutation or resource sweep is used.

Each worker runs on the local host in a fresh JDK 17 JVM with 2 GiB heap and four active processors.
It stages exactly 128 unit contributions at timestamp 1,000 microseconds, with the existing deterministic hot-row distribution and parallelism two.
The source then remains idle, allowing the completed checkpoint to own every envelope before committing.
The production writer, serializer, committer, topology checks and metadata validation remain in the path.
Table input adaptation supplies the declared writable timestamp and delegates to the actual factory-produced sink.

A loopback-only gRPC proxy forwards exact conditional requests to authenticated Bigtable with transparent mutation retries disabled.
After the eighth successful service response it returns one injected ambiguous failure, without changing the request or the service effect.
All other backend failures are terminal: subsequent calls cannot reach the service.
Production committer recovery must reuse the 128 original envelope identities.
Replay the completed checkpoint at parallelism one and three, finish stop-savepoints, and resume the last successful stop-savepoint.
Worker logs retain each first-seen protobuf envelope before forwarding and every successful response, including the discarded one.
At four readbacks, compare per-row SUM with generated distinct contributions and every marker with the original row and identity.
Empty, incomplete or inconsistent results fail the worker.
The driver requires exactly one PASS result, 128 original identities, one discarded response, at least 257 duplicate responses and 385–2,048 wire attempts.
The lower bounds cover 128 first applications, two complete 128-envelope rescale replays and at least the discarded response's replay; the nominal eighth-response-loss path yields 392 attempts and 264 duplicates.
Exactly four readbacks must each report 128 markers across the 14 rows generated by the fixed hot-row input distribution.
The local negative control must detect an unguarded extra contribution before this scenario may run against the service.
Missing metadata permission and pre-checkpoint/failed-stop boundaries remain covered locally; this lease does not change IAM or claim to repeat those service cases.

The proxy serializes forwarding and adds a local hop.
The authenticated forwarding client belongs to the worker; this lease does not measure native remote client-pool teardown or direct-connection performance.
Both production factories use an emulator endpoint for the loopback hop; the proxy's separate authenticated client connects to Bigtable.
This verifies real conditional-write/marker semantics and metadata policy through production recovery, but does not cover the connector's native TLS/ADC transport branch, service-account key loading, or its direct remote error classification.
It cannot by itself close production transport acceptance.
Its response counts and correctness results are not throughput, RPC-latency or complete-notification timing measurements.
The existing distinction between one commit invocation and a notification draining multiple earlier collections remains unchanged.
No performance gate can pass from these rows.

## Limits and cost reservation

Reserve 2,048 attempted conditional writes and 4 MiB declared write bytes before each worker, with no refunds.
Every forwarded request is at most 2,048 bytes; attempts include replay after the injected failure.
The lease ceiling is 8,192 attempts, 16 MiB declared writes and 64 MiB combined readback/metadata/monitoring allowance.
Reserve 8 MiB of reads per worker, 1 MiB for preflight, and 8 MiB for the existing post-deletion monitoring capture.
Readback is capped at 129 returned rows and 1 MiB of decoded cell material per pass; the extra allowance covers metadata and protocol overhead.
Stop at 2 GiB of owned local checkpoint data, a 240-second worker deadline, an 8 MiB worker log, or the existing lease deadlines.
Keep the 60-second checkpoint timeout.
The production correctness scenario allows 90 seconds for checkpoint/savepoint control futures and job completion, still subject to the independent 240-second worker deadline.
Other harness callers retain their existing control-future waits.
No new cell starts after 45 minutes; independent supervision starts cleanup at 50 minutes and verifies absence within the 60-minute lease.

[Official Bigtable prices](https://cloud.google.com/bigtable/pricing), checked on 2026-09-11, are USD 0.65 per Enterprise node-hour and USD 0.85 for Enterprise Plus in us-central1.
Hourly maximum-node billing and the one-hour minimum justify reserving two charged hours for this lease: at most USD 1.70 using the higher rate.
SSD costs USD 0.000232877 per GiB-hour, and outbound transfer to Japan starts at USD 0.12 per GiB.
Reserve USD 2 including storage, transfer and overhead margin; this is a conservative plan, not a billing result.

Before charging, record evidence for billed usage, a conservative unbilled bound and outstanding reservations attributable to the same authorization.
Their sum plus this USD 2 reservation must be at most USD 20.
Do not substitute the earlier below-USD-2 estimate, an empty instance list, or a missing billing export for those figures.
Missing financial evidence leaves the lease PLANNED.

## Freeze and execution prerequisites

Before creation, complete both self-reviews, Claude Max independent review and aggregate CI for the source containing this plan.
Archive the reviewed source SHA and patch, resolved dependency versions, both clean compiled classpaths and hashes of every classpath entry.
Freeze exact Java paths, JVM flags, command argument arrays, manifest hash, local archive/work paths, identities, limits, source review evidence and the financial reservation in a separate durable execution record.
The executable classpaths must reference copied outputs, never Maven directories that a later build overwrites.
No build or language-server compilation runs during service execution.

The committed entry point is `io.github.flink.gcp.connector.bigtable.sink.BigtableProductionRecoveryProbe`.
Use the existing `BigtableStage2Probe` only for `supervise`, `cleanup` and `monitor` on this lease.
The driver expands these commands into fixed argument arrays in the execution record:

1. `BigtableProductionRecoveryProbe plan <fresh-manifest>` creates the already identified PLANNED manifest without service calls; preserve it rather than generating another identity.
2. Start `BigtableStage2Probe supervise <manifest>` in an independent JVM and verify its PID/start instant and startup output before creation.
3. Run `BigtableProductionRecoveryProbe create <manifest>`, then `preflight <manifest>` once.
4. Run `service <manifest> <table>` in the four fixed positions above, with the matching frozen Flink classpath and one worker at a time.
5. Stop on the first failed, empty or incomplete observation, limit exhaustion, disappearance or unexpected process exit; record failure and signal the sibling `stop` file.
6. On success also signal `stop`, collect the supervisor result, and verify exact instance absence independently through direct lookup and an unfiltered list.
7. Verify removal of only the manifest's owned `work` child; retain manifest, commands, classpaths, logs and outcomes outside it.
8. Perform the existing bounded monitoring capture once after deletion; missing metrics remain missing and never extend the lease.

The driver supervises worker process identities and the 240-second/log/storage limits independently of the worker.
No automatic recreation, cell repetition, capacity increase or lease extension is permitted.
Ownership mismatch, unresolved creation or unavailable deletion evidence is a cleanup failure, not resource absence.
The host must remain running: the supervisor is local, not a server-side TTL.
The formal 108-cell assessment, sustained hot-row/storage measurements and supported-workload verdict remain outstanding under ADR-0165.
